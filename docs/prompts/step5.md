## 3. 確定済みの判断（再検討しないこと）

以下は 2026-08-16 に確定し、`docs/spec.md` §12-6 に書き戻し済みです。
**`/frontend-design` の中でこれらを問い直さないでください。**

### 3-1. 画面構成

| ルート | 中身 |
|---|---|
| `/` | 薄い Server Component → `<QuizRoot />`（"use client"） |
| `/review` | 別ルート。復習カード一覧 |
| `/api/feedback` | Route Handler |

`/` 内は React state による状態遷移。設定画面は作らない（テンポ設定は home の要素）。

### 3-2. 状態機械

```
boot   —(localStorage読込完了)→ home
home   —(「はじめる」)→        quiz
quiz   —(最終問題の回答確定)→   analyzing
analyzing —(AI成功 or 失敗)→   result
result —(「もう1セット」)→      quiz
result —(「ホームへ」)→         home
quiz   —(「やめる」)→           home
```

### 3-3. analyzing と result は同一レイアウトの状態差（解釈A）

画面を切り替えない。同じレイアウトで、AI 部分だけが空 → 埋まる。

理由：切り替えると「待たされた」体験が発生する。同一レイアウトなら、
結果を読んでいる最中にカードが増えるだけになる。
28秒が「待ち時間」ではなく「読んでいる時間」になる。

### 3-4. 待機中に AI 以外はすべて出す

SCORE・正解率・即答率・テンポラベル・cause の内訳を全部出す。
すべてアプリ側の計算なので待つ理由がない。読むものが多いほど28秒が埋まる。

待機中に出ないのは4つだけ：
`pattern_summary` / `review_cards` / `next_message` / `suggested_tempo`

### 3-5. AI 到着前でも「もう1セット」を押せる

28秒拘束しない。生成中の応答は破棄せず、裏で完了させてカードだけ
localStorage に保存する方針（実装が複雑なら破棄でも可。STEP 6 で判断）。

### 3-6. カードは5枚同時到着

ストリーミングは実装しない。「後から差し込む」の実態は
**28秒後に5枚同時に出る**。検証層 V1〜V6 は全件揃ってから行う設計のため、
1枚ずつ流すと不正な id が一瞬表示される可能性がある。

### 3-7. 演出

5枚同時に到着するが、表示は 0.1秒間隔で1枚ずつフェードイン。
0.5秒で全部出そろう程度の短い演出。

待機中は「分析中…」のような文言を1行だけ。**スピナーは置かない。**
SCORE と内訳を読んでもらう時間なので、視線を奪うものを置かない。

### 3-8. FEEDBACK_TIMEOUT_MS = 45000

本番実測の最大は 28.88秒。`maxDuration = 60` なので余裕15秒。
25000 のままなら5回中3回がカード未充足だった。

### 3-9. オフライン・電波不安定

fetch 失敗も AbortError と同じく pending 方式に落とす。文言も区別しない。
出題自体はオフラインでも動く（wordlist.json は静的バンドル、
SCORE 計算も localStorage もローカル）。

### 3-10. ボタン配置

主要操作（「はじめる」「次へ」「もう1セット」）は画面下部に寄せる。
片手・立ち姿勢で親指が届く範囲。選択肢4つも下寄せで縦積み。

### 3-11. 差し色・フォント・世界観

| 項目 | 決定 |
|---|---|
| 背景 | 暗め固定（通勤中・就寝前でも眩しくない） |
| 差し色1 | 緑系（正解／達成） |
| 差し色2 | 橙系（注意／復習対象） |
| 赤 | **使わない**。間違いを責める色にしない |
| フォント | システムフォント |
| 世界観 | **「静かな道具」**。励まさない、飾らない、必要なことだけ |
| タグライン | 「なぜ間違えたかが、わかる。」 |

鈴木さんは3日で挫折した人。テンションの高いアプリはもう試して失敗している。
毎日開いても疲れないことを最優先にする。
