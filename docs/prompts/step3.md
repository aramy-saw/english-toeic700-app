## 1. Vitest の導入

`package.json` に `test` スクリプトがない。最初に整える。

```bash
npm i -D vitest
```

`vitest.config.ts` を新規作成する。

```typescript
import { fileURLToPath } from "node:url";
import { defineConfig } from "vitest/config";

export default defineConfig({
  test: {
    environment: "node",
    globals: true,
    include: ["src/**/*.test.{ts,tsx}"],
  },
  resolve: {
    alias: {
      "@": fileURLToPath(new URL("./src", import.meta.url)),
    },
  },
});
```

`package.json` の scripts に追加。

```json
"test": "vitest run",
"test:watch": "vitest"
```

**`environment: "node"` にする理由**：STEP 3 は純関数のみで DOM を使わない。
`happy-dom` も `@testing-library` も不要。

**`@vitejs/plugin-react` は導入しない。** Babel の peer 依存と衝突する既知の問題がある。
React コンポーネントを描画しないため不要（my-own-video-platform での実績）。

## 3. 各モジュールの仕様

### 3-1. `src/lib/wordlist.ts`

**役割**：配布データの読み込みと型定義、`pos` の正規化。

- `WordEntry` 型を定義する（`docs/spec.md` の型定義に従う）
- 型は「配布データの7フィールド＋任意の追加フィールド」を許す形にする
  （提出後のカスタム版で `source` や `tag` を足しても型エラーにならないように）
- **`wordlist.json` を直接 import するのはこのファイルだけ。** 唯一の読み込み口にする
- `pos` の正規化：`"動詞/名詞"` → 主要品詞は先頭トークンの `"動詞"`
  - 区切りは **ASCII スラッシュ `/`**。`・` ではない
- `meaning` の分割：区切りは **`・`**。`/` ではない
- `similar` の分割：**カンマ区切りの文字列**。配列ではない
  カンマで split → trim → 小文字化してから比較する

### 3-2. `src/lib/distractors.ts`

**役割**：出題語1つに対して誤答3つを生成する。

**内訳**
- 誤答A：**異なる主要 pos** から1つ
- 誤答B：**同じ主要 pos・同じ level** から1つ
- 誤答C：**同じ主要 pos・異なる level** から1つ

**ブロックリスト（5条件）**。以下に該当する語は誤答候補から除外する。

1. 同じ `id`
2. 同じ `word`（word重複が26語あるため。**id ではなく word で判定**）
3. 出題語の `similar` に含まれる
4. 候補の `similar` に出題語が含まれる／`similar` に共通語がある
5. `meaning` に共通要素がある（`・` 分割の集合交差）

**フォールバック**

★これは例外処理ではない。**実測で必ず発火する語が2つある。**

- `id=4 available`（形容詞・L1）… 形容詞×L1 が自分1語だけ → 誤答B が構成不能
- `id=48 approximately`（副詞・L2）… 副詞が全300語で自分1語だけ → 誤答B も C も構成不能

フォールバックの段位は `docs/spec.md` の定義に従うこと。
**この2語で4択が成立することをテストで固定する。**

### 3-3. `src/lib/diagnosis.ts`

**役割**：選択結果から原因を判定する。

- 入力：出題語・選んだ選択肢・正誤・回答時間・テンポ設定
- 出力：`'pos_mismatch' | 'weak_memory' | 'hesitant' | null`

| 状態 | 判定 |
|---|---|
| 異なる pos の選択肢を選んだ | `pos_mismatch` |
| 同じ pos の選択肢を選んだ | `weak_memory` |
| 無回答・タイムアウト | `weak_memory` |
| 正解だが即答の閾値を超えた | `hesitant` |
| 正解かつ即答 | `null` |

**即答の閾値はテンポ設定で可変。** ゆっくり8秒／ふつう5秒（既定）／はやい3秒。
すべて暫定値。定数として1箇所に置く。

### 3-4. `src/lib/session.ts`

**役割**：10問の組み立て、SCORE 計算、定数の定義。

**定数**

```typescript
export const QUESTIONS_PER_SESSION = 10;
```

**コードのどこにも数字の 10 を直接書かない。**
level配分 1:4:5 も比率として保持し、問題数から枠数を算出する
（20問なら自動で 2:8:10 になる）。

SCORE 満点も `QUESTIONS_PER_SESSION * 10` で算出する（配点10/5/0点自体は固定値）。
`MAX_PENDING_PER_CALL = 5`、テンポ閾値（8/5/3秒）も定数化する。

**組み立てルール**
- 各 level 枠内で「復習カードの語 → 未学習 → 既出」の順に選ぶ
- 復習0件なら全部新規（分岐不要）
- **1セッション内で `word` が重複しない**（発見3対策）
- セッション間では除外しない（「もう1セット」で即座に再出題され、卒業判定が働く）
- 端数配分は最大剰余法（15問なら 1.5/6/7.5 → `docs/spec.md` の定義に従う）
- 枠が埋まらない場合のフォールバック順序も `docs/spec.md` に従う

**SCORE**

| 結果 | 得点 |
|---|---|
| 即答で正解 | 10点 |
| 迷ったが正解 | 5点 |
| 誤答・無回答 | 0点 |

正解率と即答率も算出する（結果画面で内訳として表示するため）。

**シャッフルは純関数として「配列を受け取って並べ替える」形にする。**
実行タイミング（クライアント側・マウント後）は UI 層の責任。

### 3-5. `src/lib/reviewCards.ts`

**役割**：復習カードのライフサイクル。

- キーは **`id`**（`word` ではない）
  - `overhead`（121「経費・間接費」）と `overhead`（287「頭上の・上空の」）は別カード
- 状態：`pending`（説明文なし）→ `ready`（説明文あり）
- **卒業条件：その語を次回以降の出題で「即答で正解」できたらカードを削除**
  - 正解しただけでは消さない。テンポの閾値をそのまま使う
- 同じ語で2回目のカードが来たら上書き
- `pending` は古い順に最大5語まで次回のAI呼び出しに渡す

**localStorage への読み書きは `src/platform/` に置く。**
`src/lib/reviewCards.ts` は「カードの配列を受け取って、更新後の配列を返す」純関数にする。

## 4. テスト仕様

各テスト対象に **「何をテストするか」と「なぜテストすべきか」** を書くこと。
ケースは「入力／期待／理由」の3列表にすること。

### 4-1. `distractors.ts`（最重要）

**なぜ**：不良問題が1つでも混ざると「原因が確定する」というこのアプリの唯一の売りが崩れる。
鈴木さんが迷うのが正しい場面で `weak_memory` と診断するのは誤診断になる。

| # | 検証内容 | 理由 |
|---|---|---|
| 1 | 誤答に `similar` 由来の語が絶対に入らない | 類義語は両方正解になる |
| 2 | 誤答に出題語と同じ `word` が入らない | word重複26語対策 |
| 3 | 誤答の `meaning` が出題語の `meaning` と共通要素を持たない | 不良問題6組対策 |
| 4 | **300語すべてについて誤答が3つ生成できる** | 全件検証。1語でも欠けたら4択が成立しない |
| 5 | `id=4 available` で4択が成立する | フォールバック必発火（現状の挙動を固定） |
| 6 | `id=48 approximately` で4択が成立する | 同上。誤答B も C も構成不能な唯一の語 |
| 7 | 同じ意味の選択肢が2つ以上出ない | 4択の成立条件 |

### 4-2. `session.ts`

| # | 検証内容 | 理由 |
|---|---|---|
| 1 | 10問 → L1:L2:L3 = 1:4:5 | 配分の基本 |
| 2 | **20問 → 2:8:10** | 定数1箇所の変更で成立することの検証 |
| 3 | 1セッション内で `word` が重複しない | 発見3対策 |
| 4 | 復習0件なら全部新規 | 分岐不要の確認 |
| 5 | SCORE：即答10点・正解5点・誤答0点 | 得点の基本 |
| 6 | 10問すべて即答正解 → 100点 | 満点の確認 |
| 7 | 10問すべて誤答 → 0点 | 下限の確認 |
| 8 | 正解率と即答率が正しく算出される | 内訳表示用 |

### 4-3. `diagnosis.ts`

| # | 入力 | 期待 | 理由 |
|---|---|---|---|
| 1 | 異なるposの選択肢を選んだ | `pos_mismatch` | 品詞の取り違え |
| 2 | 同じposの選択肢を選んだ | `weak_memory` | 記憶が薄い |
| 3 | 無回答 | `weak_memory` | タイムアウト |
| 4 | 正解・4秒・テンポ「ふつう」（閾値5秒） | `null` | 即答 |
| 5 | 正解・6秒・テンポ「ふつう」（閾値5秒） | `hesitant` | 閾値超え |
| 6 | 正解・4秒・テンポ「はやい」（閾値3秒） | `hesitant` | テンポで判定が変わる |
| 7 | 正解・4秒・テンポ「ゆっくり」（閾値8秒） | `null` | 同上 |

**6と7が重要。** 同じ回答時間でもテンポ設定で判定が変わることを固定する。

### 4-4. `wordlist.ts`

| # | 入力 | 期待 | 理由 |
|---|---|---|---|
| 1 | `"動詞/名詞"` | 主要品詞 `"動詞"` | 先頭トークン判定 |
| 2 | `"名詞/動詞"` | 主要品詞 `"名詞"` | 順序が主要用法を示す |
| 3 | `"名詞句"` | 主要品詞 `"名詞"` | 名詞句の扱い |
| 4 | `"supply, offer, give"` | `["supply","offer","give"]` | similar は文字列 |
| 5 | `"促進する・容易にする"` | `["促進する","容易にする"]` | meaning は `・` 区切り |
| 6 | 配布データ全300件の読み込み | 300件・7フィールド | データの健全性 |

### 4-5. `reviewCards.ts`

| # | 検証内容 | 理由 |
|---|---|---|
| 1 | 即答正解でカードが削除される | 卒業条件 |
| 2 | 正解しただけでは削除されない | 「迷わず出せて初めて卒業」 |
| 3 | `id` が違えば別カードとして管理される | overhead の例 |
| 4 | 同じ `id` で2回目のカードが来たら上書き | 重複防止 |
| 5 | `pending` は古い順に最大5語まで | プロンプト肥大の防止 |
