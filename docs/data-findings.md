## 9. モデル比較（2026-08-17 実測）

配布データではなく**モデル選定**の実測記録。README の「技術選定」に転記する前提で残す。

### 測定条件

**モデル以外の条件をすべて揃えた。** 同一ペイロード・同一 `route.ts`・同一ローカル環境・同日中の連続実行。

- 入力：2問（`id=4 available` 正解だが非即答 / `id=48 approximately` 誤答・品詞の取り違え）、`pending` 0件
- テンポ `ふつう`（閾値5秒）、正解率 0.5、即答率 0.0

### 判断：**Sonnet 5 を採用**（2026-08-17 確定）

1. **速くならない。** 13.81秒 → 13.40秒は誤差の範囲。Haiku に替える最大の動機（レイテンシ）が成立しない
2. **`usage_note` の踏み込みが落ちる。** Sonnet 5 は `accessible` を「到達可能性」、`obtainable` を「手続き面」と**軸を立てて**説明する。Haiku 4.5 は括弧書きの訳語（接近可能な／入手可能な）を添えるだけ
3. **`explanation` の質が違う。** Sonnet 5 は「文中でどの位置に置くかの判断でつまずいています」と症状を具体化する。Haiku 4.5 は「品詞の特徴をもう一度確認してください」と学習法の指示に寄り、§10-8 の「一般論を書かない」から外れる
4. **このアプリの主張は誤答の原因分析であり、使い分けの説明はその中核。** 速度が同じである以上、質を落とす理由がない

### 副産物：Haiku 4.5 の出力から取り込んだ改善

**Sonnet 5 の `explanation` に「閾値の5000ms」と内部の単位が出ていた。**
Haiku 4.5 は同じ入力を「5秒以内」と人間向けに変換していた。

→ プロンプトが `instantThresholdMs` をそのまま渡していたのが原因。
`secondsLabel()` で秒に変換して渡すよう変更し、禁止事項にも
「時間をミリ秒で書かない」を追加した（`cause` の内部値を排除したのと同じ趣旨）。

**比較して落とした側にも収穫があった、という記録として残す。**

### この測定で見えないこと

- **各1回のみ。分散を見ていない。** 0.4秒差は誤差と考えるべきで、同じモデルでも文章は毎回変わる
- **ローカル実測であり本番値ではない。** 本番（Vercel）の Sonnet 5 は 21.47〜28.34秒（§10-11）。Haiku の本番値は**未測定**
- **2問だけの入力。** 実運用は10問＋`pending` 最大5件でプロンプトも応答も数倍になる。そこで差が開く可能性がある
- **応答時間がモデル間でほぼ同じ理由を特定していない。** structured outputs のスキーマ処理と往復のオーバーヘッドが支配的である可能性があるが、**実測で確かめていない**
- 文章の質の評価は主観判断。数字（時間・字数）が事実、評価は判断材料
